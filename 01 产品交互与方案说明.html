核心用户与场景

谁、在什么情况下、打开 SignalLens

一句话：已有自选股、会主动看财经信息、但缺乏专业投研训练 的个人投资者 —— 在标的出现明显异动后，想快速搞懂发生了什么。

WHO

用户画像

  • 已建立自选股：有长期关注的标的，不是全市场漫游
  • 会主动看财经信息：新闻、公告、行情都会看，但时间有限
  • 缺专业投研训练：能读信息，但难以自己完成系统化拆解
  • 保留判断权：不想把决策交给黑盒，只想更快、更准地理解
WHEN

核心场景：自选股出现明显异动后

行情明显波动 大量新闻集中出现 重大公告 / 监管披露
1
到底发生了什么？把碎片信息拼成一条完整时间线
2
哪些信息真正重要？几十条资讯里找出真正影响标的的少数几条
3
为什么会影响到我的这只股票？讲清事件到股价之间的传导路径
4
哪些是事实、哪些只是推断？已发生的 vs 各方观点 vs 未来猜测
5
接下来我应该重点观察什么？给出可验证的观察指标，而不是结论
02

核心痛点：用户不缺信息，缺的是信号

问题不在“信息不够”，而在“信息太多、太难过滤”

PAIN STATEMENT
用户并不缺财经信息。真正的痛是：信息 碎片化、重复、专业、噪音高，普通投资者很难从中 识别真正影响自己标的的信号，并容易混淆事实与未来推断。

碎片化

同一件事被切成几十条短消息，分散在行情、新闻、社区，难以拼出全貌。

重复冗余

同一公告被多平台反复搬运、反复解读，真正的新增信息很少。

专业门槛高

财报术语、监管措辞、投行行话多，普通投资者消化成本很高。

噪音干扰大

标题党、情绪化评论、蹭热点内容与真信号混在一起，真假难辨。

↓ 结果
识别失败花了大量时间，仍抓不住“真正影响我标的”的那条关键信号
认知风险事实与未来推断混在一起，容易被情绪与噪音带节奏

MVP 交互流程 · 一次解释型问答的用户旅程

7 步主链路：清晰问题全自动跑通；两道 HITL 门仅按条件触发

✓正常路径：问题明确 → ② 直接放行 → ⑥ 首次完整输出，全程无需打断 →执行顺序：过滤候选 → 验证事实 → 再判断多重要 → 再解释影响 ◇CONDITIONAL HITL ①② · 仅条件触发，不是必经节点

追问与决策支持（按需）

按需通过，不是必经

核心表达规则（贯穿 ④–⑥，不单独占流程节点）： FACT 事实 · 已发生、可绑定来源 INTERPRETATION 观点 · 与事实分层标注 UNCERTAINTY 未来场景 · 不作确定性预测 同一解释中三者始终分离呈现。
RULE · FILTER

Noise Filtering 只依据 5 个维度

与信息观点方向无关 —— 过滤决定“留 / 不留”
Duplicate 重复同一事实 / 同一转载的重复表达
Relevance 相关是否与当前标的和问题真正相关
Info Gain 增量是否包含新增事实或新增证据
Source Quality 信源原始披露或可信信息源
Timeliness 时效仍处于当前分析时间窗口
Guardrail · 观点中立：SignalLens 不按观点方向过滤信息。即使与用户原有观点相反，只要相关、可信、有增量，就必须保留。 反方观点 ≠ Noise —— 反对意见、挑战信息恰是要展示给用户的部分。
RULE · RANK

Materiality Scoring · 在验证之后判断“多重要”

只评估“已通过 ④ 验证、或被明确标注尚未完全确认”的 Candidate Signal

对事实已被验证的真实新信息，评估其可能对公司的 业务 / 财务表现 / 市场预期 产生多大的实质影响。

  • 过滤回答“留不留”，核验回答“真不真”，Materiality 回答“多重要 / 排第几”
  • 高影响 Signal 进入 ⑤ 影响路径解释，并在输出中置顶
  • 打分只用于排序与解释，不预测涨跌、不构成任何建议
GUARDRAIL · 因果归因 不强行归因行情波动不强行归因：若证据无法证明某一事件是股价变化的直接原因，不把时间先后共现写成确定因果，而使用“可能驱动因素 / 相关因素”表达。
EVIDENCE STRENGTH · HIGH / MEDIUM / LOW核心 Signal 可标注证据强度。该 Confidence 只表示“当前解释有多强的证据支持”，绝不代表股票涨跌概率、收益预测或投资建议置信度。
RULE · SOURCE

Evidence Verification · Source Hierarchy（证据分级）

公司公告 / 官方披露› 权威财经新闻 │ 券商研报摘要 *› 社交平台讨论 *
公司事件事实：优先使用 公司公告 / 官方披露，其次使用 权威财经新闻；价格、涨跌幅、成交量等 市场事实直接以实时 / 历史行情数据接口为准。带 * 的券商研报摘要与社交平台讨论，仅在对应数据源接入后作为 Secondary Context / 线索层 使用，不作为当前 MVP 关键事实的 Primary Source。
优先原始来源：能找到第一方原始披露时，关键事实优先引用公司公告 / 官方披露。
冲突处理：财经新闻与公司原始披露冲突 → 以原始披露为准。
未决冲突：不强行生成确定结论，明确标注 Source conflict / 尚未确认。
Secondary Context：研报摘要 / 社媒讨论仅在数据源接入后作线索层，不作当前 MVP 的 Primary Source。
判定原则：不用“多数来源投票”来决定事实真伪 —— 权重按 Source Hierarchy，而不是按来源数量。

05

Why Agent：这不是一次 Chatbot 问答

把“看起来只是一个问题”的事拆开看，它是一条多步、多工具、持续上下文的证据链

单次问答 = 回答一个问题；SignalLens Agent = 为你的自选股跑通一条“获取 → 验证 → 解释”的证据链，并在一次会话里支持反复追问。

实时

事件是动态发生的

行情、新闻、公告随时更新，需要多数据源持续接入与跟踪。

多数据源 · 实时
去重

信息重复且爆炸

同一事件被多平台反复搬运，跨源去重与噪音过滤是强需求。

跨源去重 · 噪音过滤
相关性

“相关”要结合背景

判断一条信息是否重要，必须理解公司业务与用户自选股历史。

自选股背景 · 上下文
验证

事实必须交叉验证

关键事实需多源比对、按证据分级绑定来源，不能只信单一信源。

交叉验证 · Source Grounding
分层

事实与推断要分离

需要把硬事实、观点与未来推断拆开，这是普通解读最难的一步。

Fact / Interpretation 分离
追问

解释允许被追问

用户会继续追问，需要维持会话上下文做二次挖掘。

持续对话上下文
结论：流程是“多步骤 + 多 Tool + 持续上下文”，因此由 Agent 编排，而不是一次性 Chatbot 输出。 用户问题只是入口，真正交付的是：
多步任务编排 多数据源工具调用 持续上下文记忆 用户可复核的证据链
06

AI 自动完成 vs 用户确认（HITL · 条件触发）

只回答一个问题：哪些责任在 AI，哪些边界永远留给用户

CORE RULE

AI 负责筛选、验证和解释信息；用户保留最终投资决策权。

黄金分工线

AI 自动完成 · 整条主链路

  • 信息获取：行情 / 公告 / 新闻等多源拉取
  • 噪声过滤：去重 · 相关 · 增量 · 信源 · 时效（不按观点过滤）
  • 事实验证 / Source Grounding：交叉核对 + 按证据分级引用
  • Materiality 排序：只对已验证信号判断重要性
  • 影响分析与六段式解释输出
  • 全程可复核：结论始终绑定证据链

用户保留的节点（仅条件触发）

  • 范围澄清：标的 / 时间范围 / 问题边界歧义时确认一次HITL ① · 仅歧义 明确则直接继续，不打断自动链路
  • 决策边界：被索要“买 / 卖 / 上车”时，切 Decision Support —— 确认关注周期与风险因素，只给 Scenario / 条件 / 观察指标HITL ② · 仅交易决策请求 只会发生在首次分析输出之后
  • 最终投资决策与执行永远是用户 AI 提供解释与决策输入，不做决定与动作
07

MVP In Scope / Out of Scope

一期只做一件窄而深的事：单只自选股 × 单次事件 × 一次解释型问答

IN · MVP 范围内

  • 使用形态：单只自选股 × 单次事件 / 行情波动 × 一次解释型问答
  • 信息源：行情、公告、新闻等已接入数据，Agent 自动获取
  • 输出：六段式解释（What Happened → … → What to Watch）
  • 条件 HITL：仅歧义或索要交易决策时打断；正常问答全自动
  • 质量底线：事实绑定 Source；反方观点不过滤；未来只给 Scenario
“发现机会”在 MVP 中的定义：在用户已有自选股中识别可能构成机会或风险的重大新 Signal —— 而不是推荐用户去购买新的股票。

OUT · 明确不做

  • Buy / Sell 自动建议
  • 股票评分
  • 目标价预测
  • 自动交易 / 执行
  • 收益率预测
  • Portfolio Optimization（组合优化）
  • 全市场自动选股
  • 确定性预测未来涨跌
处理方式：用户话术命中以上任一项 → 不硬答，转入 Decision Support，只给情景 / 条件 / 观察指标。
08

产品是否成立的判断依据

一句话假设 + 一条总判断 + 可证伪的检验维度

VALIDATION HYPOTHESIS · 核心验证假设
SignalLens 能否在 不降低事实准确性、不增加用户对 AI 投资判断的过度依赖 的前提下， 帮普通投资者更快识别真正影响其自选股的重要信息，并理解这些信息的影响。
TOTAL GATE · 总判断
效率提升是收益，可信与安全是上线 Gate —— 产品成立必须同时满足 有用 + 可信 + 不越界。

即使结论来得更快，只要出现以下任一情况：关键事实准确性下降、 用户更难区分事实与推断、越来越依赖 AI 完成交易判断、 或系统出现直接 Buy/Sell 越界 —— 产品假设仍然不成立。详细量化阈值交给 03_evaluation.html。
